# Full-suite audit, 2026-11-04

Five independent reviews (project format and edits, lifecycle, render and export, Assistant and billing, copy)
returned about 90 findings. Each was treated as a hypothesis and checked while fixing. Everything here was run on
an emulator. No phone, no real provider call, no real Google Play.

## Found by tests written during the fixes, not by the reviews

- A speed curve could crash the whole app. The next speed change was rounded down onto the current time for lengths
  that do not divide evenly, and Media3 throws on that. Now rounded up. `Exporter` also turns a throw at start into
  a failed export with a message. Measured: `speedCurveWithAFadeKeepsItsTiming`, 6.45 s file for a 6.5 s project.
- Reversed clips lost about a third of their frames, and so a third of their length. The encoder's drawing surface
  skipped frames when fed quickly, and times were assigned by counting. Frames now go in one by one, with their
  exact time. Measured: 88 of 88 frames, every time from the source, 2971433 us of 2971433 us.
- Bangla project names lost their vowel signs in exported file names. Combining marks are now kept.

## Fixed: projects and edits

- Projects open on the iPhone again: required effect fields are filled in. Checked with the iPhone's own decoder.
- Import validates the id and relinks files. Sharing packs overlays, background images and colour files. Saves are atomic.
- Ripple delete and range removal close the real removed length. Reversed trims, speed with keyframes and cut snapping.

## Fixed: lifecycle

- Crash opening a project with a background and no cutout. Found by random tapping.
- One editor session across editor and export, so undo and running work survive the trip.
- Results computed from an old copy of a project are dropped with a note, never written over newer edits.
- Temp files swept, 1 GB cache limit, safe imports, keys and purchase seal survive a Keystore failure.

## Fixed: render and export

- The Normal smoothness setting really caps the frame rate. Measured: 68 fps source, 30.04 fps export.
- The export wake lock was declared and never taken. It is now taken, and limited to 6 hours.
- A finished file is no longer lost by leaving the screen: it stays until the next export, belongs to its own project,
  and earlier exports are listed with Save, Share and Delete. A notice says it finished.
- Saving failing, sound-only with no sound, and another project's export running all say so.
- Fades on trimmed clips fall at the end of the kept part. Measured: -15.1 dB steady, -18.2 dB half way, -29.7 dB at the end.

## Fixed: Assistant

- A tool that throws is an error result, never a crash. Empty answers are not stored (they broke every later request).
- Long-running tools wait for the real outcome and report failure honestly. They used to report success regardless.
- Closing the panel or opening settings no longer stops work or loses the chat.
- Gemini's thought signature is sent back. Odd answers, bad model names and Google's 400 for a bad key are handled.
- Founder looks hidden from non-Founders. `clear_effects` no longer wipes position and background.
- Default model names updated from each provider's documentation. **None has been called.** OpenRouter now defaults
  to `openrouter/auto`, which can spend the person's credit: check this before release.

## Fixed: billing

- The Plans screen updates after a purchase. Restore tells "Play did not answer" apart from "nothing found".
  Already owned reads the list again. Not run against real Play.
- By design, with no server: a phone signed in to a different Google account that owns nothing drops to Free until
  the buying account is back. Play's list is the only truth available.

## Fixed: privacy and copy

- The caption download list was fetched on opening the panel. It now fetches on a tap, as the brief requires.
- `as_network`, onboarding, privacy policy and data safety now say on-screen text the Assistant reads goes to the provider.
- Removed the false "Buying Pro arrives in a later update". Jargon removed and now banned by `BeginnerCopyTest`:
  playhead, LUT, HEVC, dB, hook, dissolve. "Model name" stays on Assistant settings, where the provider's own word helps.
- Count strings read right for any number. All 8 languages retranslated for changed strings. Not read by native speakers.

## Platform

- targetSdk 36, adaptive launcher icon with a themed form, backups exclude keys and footage. Tablets now ignore the
  orientation lock during camera recording on Android 16: not tested on a large screen.
- The clock and status icons were nearly invisible on light screens, because the base theme is a dark one. Fixed with
  `enableEdgeToEdge()`; looked at in light and dark on the emulator.

## Final checks

- Every device test except `ModelDownloaderTest` on the final code: 68 of 68 passed in 863 s. `ModelDownloaderTest` needs a
  server started by hand and was not re-run; the downloader did not change in this audit.
- Random taps: seeds 81, 82, 83, 84, 3000 events each, no crash and no freeze. The emulator itself died once during this
  run. Its own hang detector killed it (crash report in emulator code), seeds 82 and 83 were run again from a fresh boot.
- Release build, signed with the debug key: real export gives a 9:16 picture, 10 seconds, with sound, no crash.
  "Find and blur" reported nothing found on a clip with no text, so it ran but did not prove a find in that build.

## Not fixed, on purpose

- Beat sync replaces its own zoom points when run again, as the iPhone does.
- `models.zellahq.com/android/manifest.json` is a 404: only the owner can host it. See `docs/store/RELEASE_CHECKLIST.md`.

## Still unverified
